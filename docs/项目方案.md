# 2D 游戏美术资源生成器 — 项目方案

> 版本：v1.0（定稿）
> 日期：2026-10-17
> 状态：已确认技术选型，可进入开发

---

## 1. 项目背景与目标

### 1.1 背景

独立游戏开发者与小型团队在 2D 项目中普遍面临美术资源瓶颈：

- **成本高**：外包一张角色立绘或一套精灵图动辄数百到数千元；
- **风格难统一**：多人协作或多次外包容易导致素材风格割裂；
- **迭代慢**：改配色、换装备往往需要美术重新产出；
- **零散杂项多**：图标、粒子贴图、UI 切片、瓦片地图耗时但不值得外包。

AI 图像生成 + 程序化后处理已足以覆盖其中大部分环节。

### 1.2 项目目标

构建一个**桌面端 2D 游戏美术资源生成器**，让开发者通过「配置 + 提示词 + 参考图」批量生成风格统一、可直接导入游戏引擎的素材。

**一句话定位**：把美术资源从外包/手绘流程，变成「配置 → 生成 → 校验 → 导出」的流水线。

### 1.3 目标用户

| 用户群体 | 核心诉求 |
|---|---|
| 独立开发者 / Solo Dev | 快速出全套素材，成本趋近于零 |
| 小型游戏团队 | 风格统一、批量迭代、可共享风格包 |
| Game Jam 参赛者 | 极速出图，能用即可 |
| 美术人员 | 生成底稿、变体与切片，减少重复劳动 |

| # | 决策项 | 结论 |

## 3. 功能范围

### 3.1 核心功能（MVP）

1. **生图服务配置中心（Settings → Providers）**
   - 页面内添加/编辑/测试多个生图服务，随时切换默认服务
   - 内置 Provider 类型：
     - **本地 Stable Diffusion · WebUI**（AUTOMATIC1111 / Forge，`127.0.0.1:7860`）
     - **本地 Stable Diffusion · ComfyUI**（工作流 JSON 模板）
     - **OpenAI 兼容接口**（各类中转 / 云服务，自定义 baseURL）
     - **Stability AI 官方 REST**
     - **自定义 HTTP**（自定义 URL / Headers / Body 模板 / 响应提取路径）
   - 连接测试、模型列表拉取、显存/队列状态提示
   - API Key 使用 Electron `safeStorage` 加密存储，不明文落盘
2. **风格锚定（Style Anchor）**
   - 参考图 + 固定 seed + 提示词模板 + 固定负向词，组合成「风格包」
   - 风格包可导出/导入，团队共享，保证多人产出一致
3. **精灵动画帧生成（核心）**
   - 动作定义：idle / walk / run / attack / hurt 等，帧数、FPS、循环方式
   - 一致性约束：固定 seed + 参考母版 img2img + ControlNet（pose/depth）
   - 自动对齐：主体裁剪、脚底基线、水平中心轴、统一画布尺寸
   - 自动去底、去杂点、边缘羽化
   - 帧间校验（尺寸一致性 / 位移阈值 / Alpha 覆盖率），异常帧标红并可单帧重生成
4. **静态资源生成**
   - 物品/技能图标批量生成（同风格多主题）
   - UI 九宫格切片素材（按钮、面板、进度条）
5. **瓦片地图集（Tileset）**
   - 地形瓦片生成 + 无缝性检查与边缘混合
6. **预览与导出**
   - 时间轴动画预览、洋葱皮对比、逐帧微调
   - 导出 PNG（透明）+ 图集 JSON + **Godot `SpriteFrames.tres`**
   - 命名规范、尺寸缩放、帧率设置

### 3.2 进阶功能（V2+）

- 程序化生成器：粒子、光效、几何图形类素材纯算法生成（不走 AI，零成本）
- 变体批量生成（换色 / 换装 / 换武器）
- 插件化导出：Unity、Cocos
- 团队素材库与云端同步

### 3.3 明确不做（Out of Scope）

- 插画级立绘精修（定位是素材生成，不是替代画师）
- 3D 资源、音频资源
- 完整的地图编辑器（只做瓦片素材，不做关卡编辑）

## 4. 技术方案

### 4.1 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | **Electron** | 主进程负责文件系统、Provider 调用、图像处理 |
| 渲染层 | Vue 3 + TypeScript + Vite | 配置界面、任务面板、动画预览 |
| 状态管理 | Pinia | 项目/任务/风格包状态 |
| UI 组件 | Naive UI / Element Plus | 表单密集，选组件库提效 |
| 本地数据 | SQLite（better-sqlite3） | 项目、素材、任务、风格包元数据 |
| 图像处理 | sharp（主）+ node-canvas | 去底、裁切、缩放、拼图、无缝混合 |
| 导出 | 自研 Godot 资源序列化 | 输出 `.tres` + `.png` |
| 打包 | electron-builder | Windows 优先，后续 macOS |

**进程职责划分**

- **主进程**：Provider HTTP 调用（避开渲染进程 CORS）、图像处理、文件读写、任务队列、密钥加密
- **渲染进程**：UI、配置、预览渲染（canvas 播放动画）、进度订阅
- **通信**：`contextBridge` 暴露受限 API + `ipcRenderer` 事件推送任务进度（不开启 `nodeIntegration`）

### 4.2 系统架构

```
┌────────────────────────────────────────────────────┐
│                渲染进程（Vue 3）                    │
│  Provider 配置 │ 风格包 │ 任务面板 │ 预览编辑 │ 导出 │
└───────────────────────┬────────────────────────────┘
                        │ IPC（preload 受限 API）
┌───────────────────────▼────────────────────────────┐
│                   主进程（Node）                    │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────┐ │
│  │ Provider 层  │  │  生成管线     │  │  任务队列  │ │
│  │ （适配器）    │  │ （Pipeline）  │  │（并发/重试）│ │
│  └──────┬───────┘  └──────┬───────┘  └───────────┘ │
│         │                 │                         │
│  ┌──────▼───────┐  ┌──────▼───────┐  ┌───────────┐ │
│  │ 外部生图服务  │  │ 图像后处理    │  │ SQLite    │ │
│  │ 本地/云端     │  │ sharp/canvas │  │ + 文件库   │ │
│  └──────────────┘  └──────────────┘  └───────────┘ │
└─────────────────────────────────────────────────────┘
                        │
              ┌─────────▼──────────┐
              │ Godot 项目 assets/ │
              └────────────────────┘
```

### 4.3 生成管线

```
输入（动作定义 + 风格锚点 + 参考母版）
  → ① 关键姿态生成（Provider）
  → ② 一致性约束（固定 seed / img2img / ControlNet）
  → ③ 去底 + 主体裁切
  → ④ 对齐（脚底基线 / 中心轴 / 统一画布）
  → ⑤ 帧间校验（不合格标红，可单帧重生成）
  → ⑥ 排布图集 + 生成 SpriteFrames
  → ⑦ 预览确认 → 导出
```

每个环节为独立模块，允许人工在任意环节介入微调后继续流转。

### 4.4 关键技术难点与对策

| 难点 | 对策 |
|---|---|
| **动画帧间不一致**（最大风险） | ① 参考母版 img2img（denoise 0.45–0.6）；② 本地 SD 使用 ControlNet OpenPose 骨架序列强约束姿态；③ 固定 seed + 固定风格锚点；④ 云端 API 不支持 ControlNet 时，降级为「关键帧 + 程序化形变补间」 |
| 生成图背景不透明 | 统一后处理去底（阈值分割 + 边缘羽化 + 杂点清理），必要时在提示词中叠加纯色背景约束 |
| 瓦片无缝性 | 生成后边缘镜像混合 + 无缝度可视化检查（四边差值热力图） |
| 不同 Provider 能力差异大 | 适配器声明 `capabilities`（txt2img/img2img/controlnet/inpaint），UI 按能力动态启用功能并给出降级提示 |
| 本地 SD 显存/速度 | 任务队列限并发（默认 1），支持批量排队 + 断点续跑 |
| 生图成本 | 结果本地缓存（参数 hash），相同参数不重复请求；失败重试上限 3 次 |

## 5. Godot 导出规格

**输出目录结构**

```
<项目>/assets/generated/<character>/
  ├── idle.png              # 图集（横向排列）
  ├── idle.tres             # SpriteFrames 资源
  ├── walk.png
  ├── walk.tres
  └── meta.json             # 生成参数、Provider、风格包版本
```

**`SpriteFrames.tres` 结构**

- 每个动作一个 `SpriteFrames` 资源，动画名 = 动作名
- 每帧为 `AtlasTexture`（`atlas` 指向 png，`region` 为矩形）
- `speed` = FPS，`loop` 按动作配置
- 直接可挂到 `AnimatedSprite2D.sprite_frames`，或用于 `SpriteFrames` 编辑器

**兼容性注意**

- Godot 4.x 资源格式（`[gd_resource type="SpriteFrames" format=3]`）
- 默认不写入 `.import` 文件，交由 Godot 首次打开时生成；提供「仅导出 PNG」开关
- 透明通道使用 straight alpha，避免边缘黑边

## 7. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| 动画帧一致性不达标 | **高** | M1 阶段用 3–5 帧小样验证 ControlNet 方案；不达标则启用「关键帧 + 形变补间」备选方案，并明确告知用户适用边界 |
| 云端 Provider 不支持 img2img/ControlNet | 中 | 能力声明 + UI 降级提示；推荐本地 SD 作为动画帧首选后端 |
| 本地 SD 环境配置门槛高 | 中 | 提供连接向导与常见错误自查表（端口/模型/CORS 参数 `--api --cors-allow-origins`） |
| 素材商用合规 | 中 | 产物记录 Provider/模型/参数，提示用户自行确认模型许可证 |
| 范围蔓延 | 中 | 进阶功能一律进 V2 backlog，不进入 MVP |
